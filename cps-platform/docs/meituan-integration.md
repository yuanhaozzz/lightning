# 官方 CPS 接入步骤与证据

核对日期：2026-10-18。主体为个体工商户，已有备案微信小程序，尚未申请联盟账户。以下为官方公开资料可证实内容；菜单名称和准入条件必须登录后核验。

## 第一步：申请账户和登记媒体

1. 从 [美团联盟官网](https://union.meituan.com/) 进入官方后台，并核实当前账户对应的联盟产品。
2. 完成实际经营主体认证，填写与个体工商户资质一致的信息。
3. 登记自己小程序作为推广媒体，按后台要求提交 AppID、名称、用途等；建立推广位。
4. 查询开发接入/API权限入口，确认商品、转链、订单三项权限是否对当前主体开放。
5. 取得当前官方鉴权文档、签名示例、AppKey和对应密钥。密钥只保存在服务端环境变量，不能发到小程序或管理端构建产物。

[官方个人推手说明](https://123.meituan.com/serve/biz-detail/business/491/392?source=hot_51)证实个人推广工具存在，但不能证明所有个人/个体账户自动拥有API权限。备案成功也不代表联盟审核成功。

## 第二步：核对 API 体系

不要混用 `union.meituan.com` 历史接口和 `media.meituan.com/cps_open` 的鉴权实现。公开可读的当前文档：

| 用途 | 接口 | 官方文档 |
| --- | --- | --- |
| 商品查询 | POST `/cps_open/common/api/v1/query_coupon` | https://page.meituan.net/html/1701831807616_1db0df/index.html |
| 推广转链 | POST `/cps_open/common/api/v1/get_referral_link` | https://page.meituan.net/html/1701831845934_13e608/index.html |
| 订单查询 | POST `/cps_open/common/api/v1/query_order` | https://page.meituan.net/html/1706169509872_eb0353/index.html |

请求 host 为 `https://media.meituan.com`。共同要求包括 `S-Ca-App`、`S-Ca-Signature`、`S-Ca-Timestamp`、`Content-MD5`、`S-Ca-Signature-Headers`。签名时间戳为毫秒，有效期2分钟。

**尚未核实签名串顺序、HMAC类型与编码规范。当前代码没有签名实现；获得官方样例后，先用官方测试向量验证，再接入。不能用“猜到接口URL”代替可用授权。**

## 第三步：优先调通一次转链

- 选一个当前账户实际可推广的活动/商品。
- 依据官方参数使用活动ID、`productViewSign` 或支持的原始链接，避免继续使用将迁移的 `skuViewId`。
- 选择 `linkType=4`：微信小程序唤起路径。根据真实返回确认目标 AppID 和 path 的解析方式，不能预设未经证实的响应结构。
- `sid` 是渠道效果标记，最大64字符，仅英文、数字、下划线。现有本地渠道允许短横线，接自动接口时必须映射为符合上游要求的稳定标识，而不是把原值直接透传。
- 在自己的真机上主动点击跳转，检查活动、路径、优惠条件与后续跟单。
- 第一个真实订单完整走完结算，再推广更多品类。

推广链接有效期、用户归因窗口、优惠本身有效期是不同概念。不能因为链接有效就宣称永久锁粉或七天所有订单计佣。

## 第四步：逐步替换手工管理

建议服务端设置一个 `CpsProvider` 适配层：`listOffers` / `createPromotionTarget` / `syncOrderChanges`。管理端和小程序消费本站统一字段，官方密钥及签名仅留在服务端。

以下是后续实施设计，目前未冒充已实现：

1. 商品任务拉取当前可售活动、地区和佣金，保留人工上架审核。
2. 用户领取时服务端调用转链，写入渠道 `sid`，保留完整跟单参数；缓存期限服从活动与官方限制。
3. 订单按更新时间增量查询：`queryTimeType=2`，订单起止时间为秒级10位时间戳，和签名的毫秒不同。
4. 官方订单接口单页 `limit` 最大100，推荐 `searchType=2 + scrollId` 翻页，当前可查询近3个月。
5. 保存上游原始记录、订单、子券、退款、结算状态、同步游标；按稳定上游标识幂等写入。
6. 同步失败不前移游标；补拉重叠时间窗，定期对账。调度频率以后台限额和实际量确定。
7. 多券业务的父订单更新时间不能简单替代各券更新时间；增加子券查询与更新，不能只看父订单。
8. `profit` 是预估佣金。核销、平台结算、提现和银行到账分开记录。

首次API联调需准备：脱敏的官方鉴权示例、实际账户权限说明、商品响应、转链响应、订单及退款样例。不要在聊天中发送 AppSecret、联盟密钥或身份证件。
