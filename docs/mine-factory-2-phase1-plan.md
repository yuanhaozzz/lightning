### 天轮轴与接口

保留 `headframe-01/sheave` ID。当前局部轴心 [0,13.4,0]，加载比例 1.6、固定 sourceOffset [-1.225,0.59,0]，园区锚点 [-14,0,-6]，对应世界轴心约 [-15.96,22.384,-6]。轴为当前 glTF 局部 Z 方向；生成脚本 Blender Y 轴在导出时映射到 glTF 的 Z 轴，旋转正负由绳索路径校验，不能靠猜方向。

已有天轮半径 1.04 源单位，场景有效槽半径 1.664 米；提升机滚筒半径 1.1 米，导向轮半径 0.65 米。最终运动参数使用导出接口中的有效半径，确认绳中心与轮槽的偏移。轴承座、制动钳、机壳不跟随旋转件运动。

## 必要资产补充

仅在确认后进行一次性资产整理，不在设备启动、停止或故障时生成 GLB。

1. `mine-headframe.glb` 直接复用；不重建井架主体。
2. `mine-hoist-house.glb` 保持路径、建筑与设备尺寸，拆出滚筒/法兰/旋转轴/制动盘，静止轴承/制动钳/机壳分组。为观察机械运行可增加独立检修屋顶节点或局部检修视图，不能把整座机房变换成旋转物体。
3. `mine-production-links.glb` 拆出两个导向轮、固定支架、固定绳路和容器端绳段。绳路曲线与累积弧长作为可重复导出的运动接口。
4. 新增 `mine-hoist-container.glb`：通用提升容器、悬挂连接及必要导向件，明确为模拟。现有井口仅有浅井筒示意，不具完整地下空间；采用有限井口检修行程及局部查看，不能把容器摆在井架外往返，也不能让它穿过地坪/井底。行程与容器尺寸通过实际碰撞检查确定，第一阶段不开发完整地下巷道。
5. `mine-coal-conveyors.glb` 一次拆分为 `shaft-transfer`、`transfer-silo-1`、`transfer-silo-2` 三个设备组；每段保留承载带、回程带、端部滚筒、托辊及静止桁架。带面 UV 使用沿真实路径的米制弧长，避免跨段材质偏移导致逆向/横向运动。轴承与转动件不能合并。
6. 新增可复用低成本煤料源资产（建议 `mine-coal-material.glb`），包括煤块原型与煤面。运行时煤流实例化，料面按仓内有效轮廓显示，不缩放煤仓主体。仓体原文件无需为每次料位变化重新导出；保留进料口和卸料口。
7. `mine-distribution-equipment.glb` 为 12 台柜拆出独立指示灯，不重建柜体；必要时在 `mine-substation.glb` 的已有设备箱/仪表位置增加小型状态灯节点。柜门铰链、真实柜内拆解留给第二阶段。

新增动画节点使用稳定 `animationId`、`entityId`、`parentEntityId`、`role`、`pivot`、`axis`、有效半径等 metadata。同材质只在同一运动语义组内合并；重复托辊尽量复用几何，通过实例索引映射保留设备身份。加载器禁止按每个 GLB 的包围盒重新居中。

## 第一阶段运行架构

- 业务状态：`running / stopped / fault`，另有指令速度、实际速度、方向、故障原因、模拟来源。提升机的加速/匀速/减速/停靠/换向为内部工作子状态，不把这些阶段混同为故障。
- 设备状态与雷暴预警状态分开。天气演示不会自动把机械设备或 SPD 判为故障。所有值标记“演示数据”，不宣称是实时控制或实际设备运行。
- 参数配置维护设备 ID、节点绑定、轴、半径、绳路/输送路、行程、速度、加速度、料流、煤仓有效容积与初始库存。节点缺失时报错并禁止该设备启动，不静默旋转整个父模型作为替代。
- 统一 `factoryRuntime.update(deltaSeconds, viewContext)`，接入已有 `renderer.setAnimationLoop`；不增加设备级 requestAnimationFrame。逻辑积分与可见表现解耦；停止时冻结相位，恢复时连续运动。后台自动暂停，避免返回页面时突然跃迁。
- 天轮、滚筒、导向轮与容器由同一个绳位移 s(t) 驱动：转角增量为位移增量除以有效半径，方向由既有绳路包角确定。固定绳路不应随轮子绕轴乱甩；可用弧长 UV 流动显示绳移动，容器端绳长跟随容器，排绳机构与卷绕区限制在可用宽度内。
- 输送带使用连续弧长材质偏移；端部滚筒、承载/回程托辊按接触面和轴向旋转，不能转动轴承座。煤块沿槽形带面路径实例化移动，经过转载站接口后进入对应下游，不穿过罩壳或掉到桁架内。
- 三段输送由现有 from/to、trim、beltOffsets 推导真实路径，不直接使用旧占位中心线。运行联动采用下游先启动、上游先停止/排空的可配置顺序；第二/第四阶段复杂工艺可视化暂不实现。
- 两座煤仓接收各自下游到料，并考虑路程运输延迟。库存遵循输入−输出守恒，满仓阻止继续进料、空仓不产生卸料；速度不应直接等同于流量，还需要模拟截面积与堆积密度参数。两个分支比例之和不超过入料。
- 料位对应漏斗与圆柱部分的体积关系，不能用线性高度假装全仓容积线性。内部煤面从已有检修口/局部查看观察，外观保留维护良好的工业状态。
- 电力设备更新独立灯节点的颜色/少量自发光和轻量状态文字，不给整个建筑或变压器加霓虹。状态高亮与选中高亮分开；选中材质克隆/还原不能覆盖运行灯或输送带动画的 uniforms。
- 远景/被遮挡时减少托辊等不可辨识细节的姿态更新，模拟库存和累计相位仍正确；重新进入近景时同步最新姿态。停止、图层隐藏和组件卸载都正确释放资源并保留原有按需渲染机制。

## 入口与交付顺序

复用现有底部工具栏，新增紧凑“工厂运行演示”入口。全局启动/停止演示；选中设备的轻量信息中显示 ID、名称、运行状态、演示来源，提供速度/方向（有此能力的设备）、故障模拟与恢复。没有大型业务面板。

第一阶段内部依次交付：天轮与提升机运动学 → 三段输送/煤流 → 煤仓联动 → 电力灯状态 → 完整回归。上述均属于第一阶段；建筑屋顶向上分离、墙体半透明、柜门打开、爆炸图、扫描、供电线路流光与自动巡检不在此次实施范围。

## 验收与测试

1. 用实际 GLBLoader 验证节点、extras、固定坐标与加载路径；对天轮旋转一圈检查轴心、轴承和井架保持不动。
2. 不同 delta 分段（30/60/144Hz）运行相同模拟时间，绳位移、转角、到料和库存结果保持误差范围内一致。
3. 验证启动、停止、反向、故障、恢复、途中暂停与重播；容器/带面不跳回零相位。
4. 验证容器与井口、所有运动绳段、带面煤块与托辊的几何关系；轮槽接口不漂移，煤流不悬空或明显穿模。
5. 验证分流、运输延迟、满仓、空仓、下游停机/故障和质量守恒；故障传播依据配置，不把全部设备自动改成故障。
6. 验证对象拾取、图层、屋顶隐藏、内部 SPD、恢复鸟瞰及已有雷暴演示，并检查停止后按需渲染、重复加载/卸载无监听器和材质泄漏。
7. 提供园区运行、天轮/提升机近景、输煤中景、煤仓料位、配电柜状态截图，附可操作页面入口与测试报告。
8. 目标浏览器前台采样，记录 CPU 提交耗时、帧时间 P50/P95、Draw Calls、三角面数、资源体积、实例数与支持时的 GPU 耗时。上轮内嵌浏览器约 1Hz 的回调不能冒充目标设备帧率，不宣称未测得的稳定 60 FPS。

参考：Three.js 实例化复用 https://threejs.org/docs/pages/InstancedMesh.html 。本阶段机械运动优先使用参数化运动学；未来如使用 clips，AnimationMixer 仍由同一渲染循环以秒为单位更新：https://threejs.org/docs/pages/AnimationMixer.html 。
