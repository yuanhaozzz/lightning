# 雷穹 · 雷电数字孪生指挥舱 —— 产品与设计策略

> 面向中科天际（防雷监测 + 雷电预警）的客户：煤矿、电厂、电网、化工园区等央国企。
> 本文回答三个问题：**客户到底在做什么决策、数字孪生该做到哪一层、界面为什么这样排。**
> 代码实现见 `src/features/command-center/`，路由 `/command-center`。

---

## 一、先纠正一个定位：老板要的"数字孪生"，本质不是视觉

把特斯拉/鸿蒙的截图当需求，会得到两个后果：一是做出一个"好看但不可信"的看板；二是永远
做不完，因为视觉没有验收标准。

**判断：雷击防护行业的数字孪生，价值不在"把变电站渲染得多像"，而在"状态空间建得对不对"。**

真正需要被数字化的状态，是这条因果链：

```
回击发生 → 雷电流幅值 → 落点与资产的空间关系 → 保护装置是否动作、几毫秒动作
        → 设备是否受损 → 谁在什么时候闭环 → 接地电阻/SPD 是否在劣化
```

这条链上**每一环都必须有来源标注（实测 / 反演 / 预测 / 流程）**，否则它只是一个动画。
渲染精度是手段，链路可追溯、状态可回放、结论可复现才是数字孪生的定义。

**给老板的一句话**：特斯拉的价值不是 3D 车模，是它把"传感器实测 → 状态模型 → 决策建议"
这条链跑通了；我们的对应物就是上面这条防护闭环链。

## 二、三类用户、三种决策，决定三种信息层级

大屏最常见的死法，是把三类人的需求糊在同一个屏幕上。

| 用户 | 场景 | 真正要做的决策 | 需要的界面 |
|---|---|---|---|
| 值班员 / 监控中心 | 凌晨 2 点值班，常态安静 | **现在要不要叫人、要不要停机** | 实时态势 + 一键应急，越少越好 |
| 技术负责人 / 防雷专工 | 月底复盘、审计 | **哪台设备该修、哪次动作是误报** | 事件详情 + 防护闭环链 + 趋势 |
| 集团领导 | 季度检查、汇报 | **钱花得值不值、有没有系统性风险** | 资产清单 + 防护有效率的长期曲线 |

推论（这些直接决定了界面取舍）：

- 主屏**不能放"今日雷击总数"**。那是气象台的成绩单，不是指挥岗的决策输入。
  主指标换成：**当前暴露面（多少个受保护资产处在影响圈内）+ 平均防护响应时间**。
- 资产列表**只列异常的**。运行正常的资产不需要占屏，它们出现在"在线率"一个数字里就够了。
- **唯一的亮色留给告警**。全屏是深浅灰与微光，出现问题时只有一抹红 —— 这是注意力管理，
  也是高级感的来源（不是配色技巧）。
- **深色不是审美偏好，是值班场景的刚需**：连续盯屏 8 小时，亮底大屏会让值班员先累垮。

## 三、必须纠正的三个行业认知错误（技术可信度）

这三点如果做错，客户里的防雷专家会当场质疑系统，比"不好看"严重得多。

1. **闪电定位是实测，不是预测。**
   ADTD 地基闪电定位网只回答"刚刚在哪里打了多大"。而"未来 1 小时高风险走廊"属于
   **雷达外推 / 数值预报**产品，是模型预测。两者混在一个视觉层级里 = 虚假能力。
   → 已落地：`DATA_SOURCES` 台账把每一层标注为 实测 / 模型预测，走廊算法写在界面上。

2. **幅值必须落在物理量级内。**
   负地闪多数 10–60 kA，正地闪常在 100–200 kA，全球实测极值约 ±300 kA。
   演示数据里出现"250 kA 负地闪"这类值，专业客户一眼判死。
   → 已落地：`data.ts` 的幅值生成按此分布封顶 210 kA。

3. **"雷达扫描圈"这种装饰会暗示不存在的探测能力。**
   真要画探测圈，就按闪电定位站的**工程有效探测半径（约 150 km）**画站网覆盖。
   → 已落地：`SENSOR_RADIUS_KM` 驱动的覆盖层，并标注半径。

## 四、数字孪生成熟度四级 —— 建议的交付节奏

老板的期待一次说不完，但可以分四级卖，每级都有可验收的交付物。

### L1 · 时空态势层（当前版本，约 2–3 周可上线真实数据）
雷击时空可视化 + 资产风险打分 + 告警推送 + 防护闭环链。
**验收标准**：任意一次雷击，系统能在 3 秒内回答"打到哪、离谁多近、保护动作了吗、谁去闭环"。
**这是 80% 客户真正的需求**，也是唯一能立刻产生"安全生产价值"的一层。

### L2 · 资产孪生层（建议下一步，1–2 个月）
- 变电站/矿区场区**轻量 3D 孪生**：接闪杆、SPD、接地网、测点的空间位置与实时状态
- 场区级"防护覆盖仿真"：按滚球法（GB 50057）算保护范围，把**未被覆盖的死角**画出来
- 设备台账与实时数据打通（SPD 动作次数、接地电阻趋势）

**为什么这是真正的高价值层**：客户最怕的是"装了避雷针但某台设备其实不在保护范围内"。
把保护范围算出来叠在场区模型上，是我们相对纯监测厂商的**技术护城河**。

### L3 · 物理场孪生层（3–6 个月）
雷电流传导路径 + 地电位升（GPR）+ 二次设备浪涌耦合的**数值仿真与实测对比**。
这一层才有资格叫"高保真数字孪生"，但需要电磁暂态仿真能力（CDEGS / ATP-EMTP 类）与实测标定，
不是前端能解决的，需要联合高校或仿真团队。

### L4 · 预测性维护层（6 个月以上）
接地电阻劣化趋势外推、SPD 寿命预测、按区域雷暴气候的年度风险预算。

**建议对外话术**：现在是"决策指挥层"，L2 是"资产孪生"，L3 是"物理孪生"。
**千万别对外宣称已经做到 L3** —— 客户里有人懂，一次说破就丢了信任。

## 五、老板那套设计语言，翻译成什么才是对的

老板的直觉方向是对的，但需要用产品语言重新锚定，否则会变成"抄皮"。

| 老板的原始要求 | 产品化的正确表述 | 已落地设计 |
|---|---|---|
| 对标特斯拉导航 | **威胁与响应的路径可视化**，不是画条漂亮的线 | 雷暴移动轨迹 → 落点 → 资产的"威胁轨迹"，含拖尾与防御响应线 |
| 地图极致降噪 | 底层地理信息只保留**空间参照系**，其余全砍 | 暗色省界 + 国土底盘 + 能源骨架线，无 POI、无绿化、无粗边界 |
| 高保真 3D 数字孪生 | **资产状态模型**优先于渲染精度 | 微拟物发光锚点 + 红色数字角标；L2 再上真实 3D |
| 悬浮玻璃卡片 | **单位信息密度可控**，点击不丢失全局 | 极简悬浮卡片 + 底部半屏浮层，背景虚化但全景不丢 |
| 时间复盘 | **可回放的状态演变**，而不是进度条装饰 | 拖动即重绘轨迹与落点，"绘制"而非"跳变" |
| 鸿蒙四宫格 | **低频操作的收纳**，主屏永远只有态势 | 右上四宫格 + 右下应急 FAB，主屏零按钮堆砌 |
| 巨幕数字 | **核心指标降噪**，次要信息退居二线 | 暴露面/响应时间用等宽巨幕数字，辅助信息极小极灰 |

**明确不做的**：满屏红黄绿告警块、无意义扫光动效、没有数据支撑的雷达环、
只放得下演示数据的"数字艺术"。

## 六、当前版本的信息架构（为什么这么排）

```
┌─ 顶栏：品牌 / 实时接入 / 时钟 / 资产与通道计数 ──────── 右上：应急 + 四宫格
│
├─ 左栏（我看什么）                      ├─ 右栏（我该做什么）
│  1. 时间复盘轴（可拖、含告警刻度）        1. 最高优先级威胁（大字 ETA + 防护状态）
│  2. 暴露面 / 平均响应 / 有效率           2. 风险资产列表（仅异常，红色角标）
│  3. 装置动作实况（孪生体的"心跳"）        3. 每行右侧 i → 半屏浮层详情
│  4. 图例 + 数据来源台账（实测/预测）
│  5. 比例尺（暗色航图必须有尺度感）
│
├─ 底部：视图胶囊（态势/资产/告警/复盘）+ 胶囊通知
└─ 浮层：雷击事件详情 = 巨幕电流 + 防护闭环链 + 联动设备 + 近 90 分钟活动
```

四个设计原则：

1. **左栏回答"发生了什么"，右栏回答"我该做什么"** —— 视线左右分布即决策闭环。
2. **事件详情页的主角是防护闭环链**（捕获→反演→匹配→动作→闭环），不是那串数字。
   这是把"看板"变成"孪生体"的关键一页，也是审计时唯一拿得出手的页面。
3. **渐进式模糊** 只用于表达层级：浮层升起时地图虚化、全景不消失，收起即恢复。
4. **一切结论可溯源**：数据来源台账常驻在左栏底部，走廊算法写在界面上。

## 七、下一步建议（按性价比排序）

1. **接真实数据**：把 `data.ts` 换成后端接口，优先闪电定位 + 装置动作流。
   在拿到真数据前，任何视觉优化都可能是错的方向。
2. **做 L2 场区资产孪生 + 滚球法保护范围覆盖**（最大差异化，技术护城河）。
3. **建立防护闭环的工单闭环**（没有闭环，"数字孪生"就还是监控屏）。
4. **补一套真实雷击个例回放**：拿一次真实雷暴过程做 3 分钟演示，比十页 PPT 有用。
