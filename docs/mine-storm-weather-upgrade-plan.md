# 煤矿雷暴天气系统视觉升级方案

日期：2026-10-12。当前文档为实施方案，不代表天气功能已经完成或通过性能验收。

## 当前实现与问题

- `stormCloud.ts` 已使用 WebGL2、Data3DTexture、GLSL3、48 步 Ray Marching，不是 GLB 云模型。密度与预烘焙照明共用 RG8 体纹理，144×64×104，1,916,928 字节，单个代理盒 12 三角形、1 Draw Call。
- `stormCloudDensity.ts` 的水平包络仍由椭圆半径约束。顶部高度变化、噪声侵蚀和相对平坦的底部已经存在，但形态不足以形成大尺度积雨云的垂直发展与不规则云砧。
- `stormCloudState.ts` 当前配置跨度 310×220 米，底部 32 米、顶部 104 米，位置从 [-48,68,-95] 移动至 [-12,68,-55]。这是原来的展示尺度，不能当作真实气象尺度。
- `index.vue` 的主相机 far=5000 米；近景设备允许小 near。简单把 far 增至数万米存在深度精度风险；原有将园区与整片云一并拟合的相机算法，也会把约百米尺度的园区缩成小点。
- 当前云内闪光为四组固定时刻、局部指数衰减的亮度注入；没有云地闪电通道、降雨和湿润反馈。
- 当前 45 秒状态机为正常 5 秒、预警 40 秒。预警触发时间和云团出现互相绑定，需要拆开天气阶段与设备状态。
- 当前环境云影是一张水平透明软阴影，不能承担山坡和建筑上的天气遮蔽。

## 推荐架构

保持 Three.js WebGL2、现有 GLB、业务实体 ID、OrbitControls、拾取、屋顶隐藏与模拟演示入口。无需 Cesium、天气 GLB 或新的大型渲染库。

场景和天气共享坐标与时间，分开渲染责任。场景主相机保留适合设备近景的裁剪范围；天气通道使用同一相机位置、朝向、FOV 和世界射线，独立处理公里级体积范围。云体进入低分辨率 RenderTarget，经不透明场景深度限制积分距离，并进行深度感知合成。远方云可以出现在天空中，山体和建筑必须正确遮挡它。透明玻璃、雨幕与云层的合成顺序单独验证。

第一版不引入复杂 TAA；采用稳定抖动、渐进采样、空域跳过和透明度早退。暂停时冻结随机种子、风场与全部视觉时钟。必要时再引入历史重投影，避免过早产生拖影和闪电残影。

## 配置与米制尺度

新增独立天气配置，至少包含：地面标高、云底离地高度、云顶离地高度、水平范围、风向/轨迹、雨区、强度、随机种子、事件时间和画质档位。

首轮调试预设：云底 1500 米、云顶 9000 米；允许在用户指定的 1200–2000 米、7000–11000 米区间及配置允许范围内调整。水平覆盖与移动距离以公里级天气单体调试，不能沿用 310 米宽的旧比例。以上为演示配置，不是实测气象数据。

云底/云顶必须对应实际密度体的高度定义，不能只修改代理盒尺寸而让有密度区域偏离配置。同时计算云底与周围山体的关系，避免云体穿过不应被覆盖的山坡。

园区主视角保持原有观察尺度，不强求把 9 公里高的完整积雨云和百米尺度的园区同时塞入同一镜头。主视角展示云底、局部云体与雨区；复用现有天气观察入口提供更远的天气形态视角。相机距离变化不改变云体世界尺寸。

## 积雨云

使用天气覆盖场、云型高度剖面、域扭曲的低频噪声与高频侵蚀噪声组合密度。通过不规则对流区域形成几处相互连通的上升塔、偏移扩展的云砧和厚实云底，移除单一椭圆轮廓约束；不堆叠实心球。

着色采用消光积分、太阳方向的少量光程采样、环境散射与多次散射近似。顶部较亮、内部密度层次清楚、底部深灰但保留散射亮度。轮廓通过密度渐变形成软边，而不是代理盒硬边。

3D 噪声和覆盖纹理可复用，初次生成放入 Worker，避免页面主线程等待。高、中、低画质共享同一云体轮廓与物理尺寸，只调整采样和渲染分辨率。

## 闪电

云内事件通过带种子的事件表生成，具有变化的时间、位置、能量、持续时间和回击组。局部光源项注入云体积分，考虑周围密度，避免整团云同时变白。暂停/继续不重抽随机数，重新播放同种子可复现。

云地通道由世界空间递归扰动折线和少量分支形成，采用可控屏幕宽度的细通道与低强度光晕。事件短促、稀疏，允许少量连续回击；不依靠频繁全屏曝光闪白。终点须采样实际地形高度，不能落在地面下或悬空。

闪电光源采用有限作用距离的短暂动态灯光与云内局部发光，照亮附近地面、山坡、建筑和雨幕。第一版不为每次闪电创建动态阴影贴图。事件数据标记 `source: '演示数据'`，保留世界坐标、事件类型、时间和 ID；真实事件使用独立来源字段，当前不接真实接口。

## 降雨与环境

雨区由天气覆盖场与降雨强度共同控制。远景为少量世界空间雨幕/体积衰减区域；近景为相机附近、仍受世界雨区裁切的 GPU 实例雨丝，位置在 shader 中由统一时间计算，不逐帧在 CPU 重建几何。相机进入屋顶下和配电室内部时，雨丝需要被遮挡；不在室内直接降雨。

雨滴数量、长度和透明度按画质、相机距离及雨强调整。避免每滴雨创建一个 Three.js 对象。远景雨幕与能见度衰减相配合，不能通过全局浓雾把非雨区也遮住。

环境响应包括缓变的直射光/环境光、距离雾、低频云影和雨区湿润度。云影在地形与建筑表面按世界坐标采样共享天气遮蔽场，保留现有工业结构阴影。湿润度通过运行时材质扩展降低粗糙度并适度压暗表面，按材质区别处理玻璃、金属和混凝土；不覆盖 GLB 原材质贴图，不修改资产。退出后恢复材质、灯光、雾及原始场景状态。

## 45 秒时间轴

采用可配置节点及平滑插值，建议首轮：0–10 秒接近；10–18 秒出现云内放电；18–30 秒局部降雨逐渐建立；30–45 秒雷暴增强并触发模拟预警。边界与强度均可配置。

保留播放、暂停、继续、重播、退出、演示记录和设备 ID。天气阶段与设备正常/预警/异常状态分离，SPD 和接地设备不因雷暴自动故障。所有天气、设备、镜头动画读取同一演示时间；退出淡出是控制器管理的统一结束过渡。手动操作暂停自动镜头，不强行锁住 OrbitControls。

在现有演示控制中增加紧凑的云/雨/闪电开关和画质选择，不新增业务面板。效果开关不重置设备演示状态或事件历史。

## 画质与测量

建议作为测试起点，而非性能保证：低档云分辨率 0.4、24 步；中档 0.5–0.6、40 步；高档 0.75、64 步。近景雨丝预算分别约 1000/3000/6000 个实例，按屏幕覆盖和实际 GPU 数据调整。降档先减少采样成本，保留物理高度、轮廓和关键照明反馈。使用迟滞避免档位震荡。

验收记录浏览器版本、可见/后台状态、实际 WebGL renderer、CPU/GPU、视口、DPR 和画质。暖机后重复采样，报告平均 FPS、帧时间 P50/P95、CPU 提交耗时、总/天气 Draw Calls 和 GPU 耗时。

GPU 计时用 `EXT_disjoint_timer_query_webgl2` 异步查询，不使用 CPU render 时间冒充 GPU 时间；不支持扩展或发生 disjoint 时明确标记不可用。WebGL 无通用精确显存读取接口，提供纹理/几何/RenderTarget 分配估算并与实际驱动显存测量区别标注。

上轮内嵌浏览器样本为约 1004 毫秒动画回调间隔，不能用于宣称桌面浏览器达标；前台目标浏览器验证是最终性能验收的必要环节。测试过程中若无法取得有效 GPU 计时或前台帧率，保留缺失项，不补造数值。

| `mineEnvironment.ts`, `terrainMaterials.ts` | 雨区雾、共享云影、地表湿润与退出恢复 |

拟新增：`weatherConfig.ts`（配置/档位）、`weatherTimeline.ts`（纯时间求值）、`weatherSystem.ts`（统一协调）、`weatherRenderPass.ts`（深度合成）、`weatherNoise.worker.ts`（噪声生成）、`stormLightning.ts`（通道/放电灯光）、`stormRain.ts`（雨幕/雨丝）、`weatherMaterialResponse.ts`（材质响应与恢复）、`weatherPerformance.ts`（异步 GPU 计时/分配估算）、`weatherSystem.check.mjs`（回归检查）。职责拆分可在实施时按实际复杂度合并，不为空文件凑架构。

不改 Blender 脚本、GLB 文件、园区布局配置、设备 ID、其他业务路由。现有保护基线不静默重写；对授权修改的天气源文件建立版本化迁移记录，继续验证资产和其他交互未改。

## 分阶段交付

1. **云体、尺度、构图**：先建立天气配置与测量基线，再完成不规则密度、米制高度、天气通道和正确遮挡。交付主园区/云底/远方积雨云三种视角；此阶段不实现新降雨或云地闪电。
2. **局部云内放电、环境响应**：引入统一天气时间轴、非周期事件、光照/能见度/云影响应。验证暂停画面稳定、重播可复现、退出完整恢复。
3. **降雨、湿润、云地闪电**：依次加入并分别验证雨区、屋顶遮挡、落点、分支、回击、局部照明和模拟标识；每项可独立关闭。
4. **整体验收与性能收敛**：完整 45 秒演示、三档画质、真实目标浏览器性能、显存分配估算、重复启动退出的泄漏检查，以及建筑拾取、配电室内部、SPD、图层、恢复鸟瞰回归。

每阶段保留对比截图和测量结果，再推进下一阶段，不一次性替换全部天气效果。
