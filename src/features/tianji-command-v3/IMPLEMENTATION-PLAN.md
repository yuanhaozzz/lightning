# V2 沉浸式升级 · V3 模块实施记录

需求原文见 [REQUIREMENTS-V2.md](./REQUIREMENTS-V2.md)。用户要求继续编写后，已延伸实现云团、轨迹和资源加载接口。UI 由用户验收，不进行浏览器自动巡检。用户确认没有地形/矿区模型数据，真实资源验收仍待数据接入。

## 第一阶段：现状与风险

- 已检索项目及父目录的 AGENTS.md / CLAUDE.md，未发现适用文件。
- 实际入口为 `/tianji-command-v3`，现有 v3 使用 Three.js，而非需求背景中的 Cesium。
- 项目已经安装 Cesium，Vite 已配置 Cesium 静态资源；无需新增依赖或更改构建。随后发现 `App.vue` 的 v3 分支仍挂载 V2，已修正为 V3，否则新场景无法显示。
- 已有 UI、时间轴、六个图层、双向雷暴/矿区选择与轨迹首次影响算法，继续复用。
- `commandDemo.ts` / `weather.ts` 都是模拟数据。矿区坐标也是场景样本，不能宣称是核验后的真实监测资产。
- 原 overview 分支强制使用 T06、78 km / 18 min。18 min 并非轨迹计算结果；本轮将开场与点击分析统一。
- 原有模拟预警等级采用 `warningLevel` 的距离阈值。本轮沿用该规则，不另造等级；全国开场在已确认轨迹命中的关系中按既有等级、首次影响时间、强度排序。接入真实接口时须改由业务等级字段提供结论。
- 距离口径继续是当前圆形云团边界到矿区中心的球面距离；ETA 是未来 180 分钟预测路径首次覆盖矿区的时间，包含方向、半径和是否相交。测距线用 Cesium 椭球插值绘制，不暗中替换业务算法。
- 已有本地 Natural Earth 影像与可选 `VITE_TDT_KEY` 天地图影像配置。未发现已授权的真实高程地形、矿区建筑/设备模型；本轮保留椭球地表并明确标注。影像不等于高程数据。
- 现有云团半径达到 105–180 km，同时容纳完整云团和矿区的最终构图仍属区域态势视角，不能承诺该构图能看清单栋设备。后续近距离下钻需单独设计。

## 第二、三阶段：本轮实施

| 文件                     | 职责                                                                                   |
| ------------------------ | -------------------------------------------------------------------------------------- |
| `sceneTypes.ts`          | 场景接口、演示状态、屏幕安全区域、性能数据契约                                         |
| `cinematicCamera.ts`     | 全国→目标锁定→远/中/近景飞行→2.8 秒测距→自由交互；统一取消、异常恢复和减少动态效果支持 |
| `cesiumScene.ts`         | Cesium 场景适配、既有数据图层、批量事件点、测距线、标签投影、资源回收                  |
| `stormEffects.ts`        | 原生程序云团、分层示意高度、轨迹流动点、模拟事件触发的雷击光效、云团数量分级           |
| `geographicResources.ts` | 可配置地形/3D Tiles、按距离加载、超时降级、切换目标释放资源和加载指标                  |
| `commandAnalysis.ts`     | 移除开场虚拟 ETA 覆盖；复用既有关系算法选取全国目标；无预测显示“暂无法估算”            |
| `index.vue`              | 演示状态、跳过/重播、切换矿区、距离数字动画、数据状态、开发性能面板                    |
| `immersive.css`          | 仅作用于 v3 的紧凑布局、Cesium 容器、信息层次和移动端样式                              |
| `REQUIREMENTS-V2.md`     | 保留用户需求原文                                                                       |

保留旧 `commandScene.ts` / `weatherScene.ts` 作参考，当前入口不再导入它们。其他版本、业务页面和已有未提交修改不在本轮修改范围。

相机根据云团整个圆形边界和矿区形成包围球，再结合相机视锥、容器长宽比与 UI 预留区域计算距离和偏移；最终倾斜角约 45°。飞行总时长按当前距离限制在 4–9 秒；各阶段缓入缓出。使用递增执行编号拒绝旧完成回调，只允许一次飞行。用户操作、目标切换、隐藏页面和相关图层关闭均可取消。

首次进入执行一次；同一页面运行期重新挂载路由不会自动再播。显式重播始终可用。无有效危险目标时保持全国视角。未接入后端会话持久化，刷新浏览器会重新成为首次进入。

测距以缓存的当前边界→矿区路径展开，数字、方向、速度、ETA 分阶段揭示。零距离显示覆盖端点，不绘制无意义的零长连线。轨迹与事件跟随同一个模拟分钟值，计算与绘制分离，时间轴 1× 每真实秒推进 15 秒场景时间。

## 后续阶段实施与剩余边界

1. 第四阶段：完成地形/3D Tiles 配置入口、按距离加载、超时与失败降级、旧目标模型释放、地形碰撞开关、贴地矿区标记及加载指标。用户没有资源地址，当前不展示真实地形/建筑；未进行真实数据源验收。配置方式见 README。
2. 第五阶段：用原生 CloudCollection 替换透明椭球代理，加入分层示意高度、噪声切片缓慢变化、轨迹流动点和时间轴模拟雷击脉冲。最多 48 个云团单元，低配置减至 24 个，全国视角减至 16 个。所有位置跟随同一模拟时间值，真实高度仍缺少数据来源。
3. 第六阶段：补充像素密度限制、飞行期间低帧率降档、静态防御圈缓存、可复用特效集合、后台暂停、资源释放及扩展性能面板。真实监测后端、真实设备性能基线、长期资源稳定性与完整 UI 验收尚未完成。

## 验证边界

此前镜头阶段执行过类型检查、构建和既有计算回归；本次续写未重新运行测试或浏览器巡检，不能视为整体验收通过。开发面板的 FPS 是实际提交渲染帧的速率，按需渲染下静止画面低 FPS 不代表卡顿；Heap 仅在浏览器提供时显示，顶层 Primitive 数不等于 GPU 显存。未接入的地形/建筑加载时长、不可获得的 GPU 显存不伪造数值。
