# 雷电数字孪生系统 V2.0 — 沉浸式三维态势感知升级需求

## 一、项目背景

当前项目已经完成雷电数字孪生系统的初版开发，具备全国雷暴态势展示、危险矿区定位、雷暴云团、雷暴移动轨迹、威胁距离、预计到达时间、图层控制和时间轴等功能。

目前存在的问题：

1. 地图整体偏向二维科技可视化，缺少真实三维空间纵深。
2. 自动定位危险矿区的过程比较普通，缺少电影级镜头语言。
3. 雷暴云团偏向平面效果，缺少真实的云体层次与空间感。
4. 矿区和云团之间的距离、移动方向、威胁关系缺少直观的动态表达。
5. 当前界面虽然具备科技感，但整体仍偏向传统 GIS 可视化大屏。
6. 三维地形、建筑、雷暴云团与业务数据之间缺少统一的视觉叙事。
7. 现有系统需要进一步提升动画流畅度、场景加载效率和交互体验。

本次开发不是推翻重做，而是基于现有系统进行升级。

目标是打造具有电影级空间表现、真实地理信息、动态威胁分析能力的沉浸式雷电数字孪生系统。

## 二、技术约束

当前阶段使用：

- Vue 3
- TypeScript
- Cesium
- GSAP（如现有动画方案不足，可按需引入）
- 现有项目 UI 组件及状态管理体系

暂时不引入：

- Aholo
- Three.js
- Unreal Engine 5
- 3D Gaussian Splatting

原则：

1. 优先使用 Cesium 原生能力。
2. 保留现有技术架构与业务功能。
3. 不为视觉效果引入不必要的复杂依赖。
4. 所有三维场景必须可以真实交互，不允许使用视频或静态图片伪装三维场景。
5. 模拟数据和真实监测数据必须明确区分。
6. 优先复用现有地图、云团、时间轴、矿区及数据处理模块。

## 三、核心用户体验

### 3.1 系统首次进入

用户进入页面后，系统自动执行一次沉浸式态势演示。

演示流程：

全国雷暴态势
→ 自动识别危险矿区
→ 高亮目标矿区
→ 镜头平滑飞行
→ 进入真实三维地形
→ 锁定矿区与雷暴云团
→ 动态绘制威胁测距线
→ 展示距离、速度、方向、ETA
→ 进入可自由交互的三维态势场景。

要求：

- 自动演示只在首次进入或用户主动重播时执行。
- 存在多个危险矿区时，按照现有风险等级及业务规则选择目标。
- 不得自行根据距离虚构风险等级。
- 没有危险矿区时，停留在全国态势视角。
- 用户可以跳过演示。
- 用户主动拖动、缩放地图时，应停止自动镜头动画。
- 用户切换矿区后，重新计算镜头目标和威胁关系。
- 演示结束后不得自动重复播放。

## 四、电影级镜头飞行系统

这是本次升级的第一优先级。

### 4.1 全国态势阶段

进入页面后，地图首先展示中国区域的雷暴整体态势。

视觉效果：

- 地图逐渐清晰呈现。
- 危险矿区以柔和的呼吸光圈高亮。
- 当前目标矿区出现定位扫描效果。
- 其他矿区降低视觉权重。
- 镜头开始向目标区域平滑推进。

不得使用频繁闪烁、过度发光或夸张扫描效果。

### 4.2 镜头飞行阶段

基于 Cesium Camera 实现电影级空间飞行。

要求：

1. 从全国视角逐步飞向目标矿区。
2. 镜头运动具有明显的空间纵深。
3. 根据距离自动调整飞行速度和动画时长。
4. 采用平滑缓入缓出曲线。
5. 避免镜头突然跳变。
6. 镜头高度逐渐降低。
7. 镜头俯角逐渐变化，最终形成约 45° 倾斜观察效果。
8. 避免镜头穿透地形、建筑。
9. 相机目标与矿区、云团的位置保持关联。
10. 飞行过程中不应出现地图空白或严重的资源加载闪烁。

镜头运动不应只是简单的 camera.flyTo 放大。

需要设计具有阶段感的相机运动，包括远景、中景、近景以及最终构图。

### 4.3 最终镜头构图

镜头最终停止时，必须同时看到：

- 目标矿区
- 雷暴云团
- 云团与矿区之间的空间关系
- 威胁距离
- 移动方向
- 关键预警信息

不能只把矿区放在屏幕中央，而导致云团被裁切。

需要根据矿区坐标、云团范围、地图容器尺寸和 UI 遮挡区域动态计算最佳观察位置。

最终视角建议为 35°–55° 倾斜观察，具体角度根据场景自动调整。

## 五、真实三维地理场景升级

### 5.1 地形展示

保留 Cesium 地图底座。

当镜头进入目标矿区附近时：

- 展示真实地形起伏。
- 增强山体、地面、建筑的空间纵深。
- 根据距离逐步加载更高精度地形。
- 合理使用光照、阴影和环境效果。
- 保证矿区位置与真实经纬度一致。

优先使用项目已有且具备授权的数据源。

如果缺少真实三维地形或建筑数据，需要明确指出，不得通过虚构建筑替代真实矿区并宣称其为真实场景。

### 5.2 三维建筑

调研现有 Cesium 3D Tiles 加载能力。

支持时：

- 加载真实建筑或矿区模型。
- 根据相机距离调整模型细节。
- 避免远距离加载不必要的高精度资源。
- 允许在目标矿区附近查看建筑和设备的空间分布。

若当前没有真实建筑数据，先完成地形与镜头系统，建筑部分预留接口。

### 5.3 远近景视觉过渡

远景：

突出全国雷暴分布和危险矿区。

中景：

突出雷暴云团、地形及矿区位置。

近景：

突出矿区建筑、雷暴空间关系和威胁测距。

不同层级使用不同的标签密度、视觉效果和数据细节，避免所有内容始终同时显示。

## 六、雷暴云团三维视觉升级

### 6.1 云团外观

保留当前雷暴云团数据与展示逻辑。

优化目标：

- 云团不再只是平面发光圆斑。
- 增加柔和边缘和内部层次。
- 使用多层透明度、程序纹理或适合 Cesium 的自定义材质增强体积感。
- 云团内部具有缓慢流动效果。
- 云团亮度根据视觉需要进行适度变化。
- 云团范围应与实际雷暴区域数据保持一致。

注意：

不要求第一阶段实现完整物理体积云渲染。

优先实现具有空间感、性能可控的近似云体效果。

### 6.2 云团高度

如果接口提供云底高度、云顶高度或雷暴回波高度数据，则按真实数据展示。

如果没有：

- 不允许生成虚假的真实高度。
- 可以使用明确标注的演示高度进行视觉验证。
- 真实业务界面应隐藏无法确认的高度指标。

### 6.3 云团动画

支持：

- 云体缓慢流动。
- 根据轨迹数据更新云团位置。
- 云团运动方向指示。
- 适量雷电闪光。
- 轻微能量扩散效果。

要求动画连续、自然，不出现明显跳帧。

### 6.4 云团选中效果

点击云团时：

- 不使用大面积高亮遮挡云体。
- 采用轻量化轮廓、定位角标或边缘辉光。
- 云团内部细节保持可见。
- 相关文字始终清晰。
- 不出现标签相互遮挡。

## 七、雷暴与矿区动态威胁测距

这是本次升级的第二个核心亮点。

### 7.1 动画触发

镜头飞行结束后，自动开始测距动画。

执行顺序：

1. 矿区出现定位光圈。
2. 云团出现柔和高亮。
3. 两者之间逐渐生成测距线。
4. 测距线沿路径向目标延伸。
5. 距离数字从初始值递增到计算结果。
6. 显示云团移动方向。
7. 显示移动速度。
8. 最后显示预计到达时间。

整段动画建议控制在 2–3 秒。

### 7.2 测距线设计

采用轻量化科技视觉。

建议：

- 主线为青蓝色。
- 危险状态使用琥珀色强调。
- 线条具有适度发光效果。
- 沿线存在低频流动粒子。
- 起点与终点具有小型定位标记。
- 不使用大面积光柱和粗线条。

要求：

- 地图旋转时测距线正确跟随。
- 地图缩放时线条视觉粗细合理。
- 云团移动时更新位置。
- 不遮挡主要地形和建筑。

### 7.3 距离计算

优先复用现有业务距离计算逻辑。

需要确认当前距离的业务定义：

- 云团中心到矿区中心的距离；
- 云团边界到矿区的最近距离；
- 或雷暴预测轨迹到矿区的距离。

不能在未确认业务口径的情况下直接替换计算方式。

若采用地表距离，使用真实经纬度及椭球测地计算。

展示单位：

- 小于 1 km 时可以展示米。
- 大于等于 1 km 时展示 km。
- 保留合理小数位。

### 7.4 预计到达时间

ETA 必须基于有效的雷暴移动数据计算。

需要考虑：

- 当前距离
- 移动速度
- 移动方向
- 是否朝向矿区
- 轨迹预测有效性

不能简单使用距离除以速度作为所有情况的 ETA。

没有可靠预测结果时，显示“暂无法估算”。

## 八、雷暴移动轨迹

保留现有雷暴轨迹功能。

优化内容：

1. 使用细线表达历史移动路径。
2. 轨迹上增加方向流动动画。
3. 历史路径与预测路径采用不同线型。
4. 历史路径使用低饱和度青蓝色。
5. 预测路径使用虚线或渐隐效果。
6. 当前云团位置明显高亮。
7. 支持按照时间轴回放。
8. 回放过程中同步更新云团位置、测距线和威胁指标。

避免在地图上堆叠大量箭头、文字和装饰性图标。

## 九、UI 与视觉系统升级

保留现有深色科技感视觉方向。

总体原则：

地图是主体，UI 是辅助。

### 9.1 顶部导航

保留：

- 系统 Logo
- 实时态势
- 能量场分析
- 轨迹推演
- 威胁预警
- 时间和必要状态信息

优化：

- 降低顶部区域高度。
- 减少过度装饰。
- 使用精细的线条与微弱辉光。
- 保证地图视野。

### 9.2 左侧态势信息

保留核心指标：

- 雷电事件数量
- 活动雷暴数量
- 受威胁资产数量
- 监测矿区数量

采用简洁数字排版。

减少大面积卡片背景。

### 9.3 危险矿区信息

矿区被锁定后，显示：

- 矿区名称
- 当前威胁等级
- 雷暴距离
- 预计到达时间
- 移动速度
- 移动方向

信息面板应轻量、紧凑，避免遮挡目标。

### 9.4 右侧图层控制

保留现有图层开关。

采用可收起的小型毛玻璃面板。

不增加不必要的功能按钮。

### 9.5 底部时间轴

保留时间轴与播放能力。

要求：

- 历史、当前和预测时间明确区分。
- 支持播放、暂停、倍速。
- 支持拖动进度。
- 时间轴尽量降低高度。
- 不遮挡地图主要目标。
- 回放期间地图数据与时间状态同步。

### 9.6 整体视觉规范

主色：

深海军蓝、青蓝色。

强调色：

琥珀色，用于危险预警。

避免：

- 大量霓虹描边。
- 过度使用发光边框。
- 大面积不透明卡片。
- 无意义的动态扫描。
- 装饰性元素遮挡业务数据。

整体追求精密、克制、具有空间纵深的科技感。

## 十、交互与动画管理

需要建立统一的自动演示状态管理。

建议状态：

- INITIALIZING：初始化
- OVERVIEW：全国态势
- TARGET_LOCKED：锁定矿区
- FLYING：镜头飞行
- MEASURING：威胁测距
- INTERACTIVE：自由交互
- INTERRUPTED：演示中断
- ERROR：异常状态

要求：

1. 不允许多个相机动画同时运行。
2. 用户操作能够中断自动演示。
3. 切换矿区时取消上一次动画。
4. 图层关闭时停止相关动画。
5. 页面卸载时清理所有事件和定时器。
6. 支持演示重播。
7. 支持动画失败后的安全恢复。
8. 不因动画异常导致整个地图不可操作。

## 十一、性能与工程化

这是项目必须重点体现的能力。

### 11.1 地图加载

- 优先保证地图主体快速显示。
- 三维地形和建筑按需加载。
- 远景不加载不必要的高精度模型。
- 避免切换视角时出现长时间空白。
- 保留必要的加载状态与错误降级。

### 11.2 渲染优化

- 避免每帧创建大量 Cesium Entity。
- 高频动态效果优先评估 Primitive 或批量渲染。
- 降低不必要的材质更新。
- 地理距离计算与动画渲染解耦。
- 根据设备性能控制粒子数量和后处理效果。
- 对静态场景评估按需渲染策略。
- 保持场景交互流畅。

### 11.3 资源管理

- 地图资源按需加载。
- 缓存可复用的模型与纹理。
- 页面卸载时释放相关资源。
- 防止重复注册事件监听。
- 防止重复创建动画循环。
- 避免长期运行后内存持续增长。

### 11.4 性能监测

增加开发环境性能监测能力：

- FPS
- 场景初始化耗时
- 首次可交互时间
- 镜头飞行耗时
- 地形和模型加载耗时
- JS Heap 变化
- 可获取的 GPU 资源指标

性能目标：

以测试设备和现有基线为准，优先保证交互流畅。桌面端以稳定接近 60 FPS 为优化目标，不将其作为所有设备上的硬性承诺。

## 十三、最终验收标准

1. 系统打开后自动锁定当前危险矿区。
2. 镜头能够从全国态势平滑进入矿区。
3. 最终镜头能同时展示矿区和雷暴云团。
4. 近景能够体现真实三维地形空间感。
5. 动态测距线具有完整的生成动画。
6. 距离、速度、方向及 ETA 与业务数据保持一致。
7. 云团具备明显的空间层次与动态效果。
8. 用户能够随时中断、重播和切换矿区。
9. 原有业务功能正常。
10. 动画及资源不会造成明显的内存泄漏。
11. 所有演示效果必须是真实运行的前端场景。
12. 真实数据与模拟数据明确区分。

## 十四、Codex 执行要求

请严格遵循以下流程：

第一步：阅读现有项目的 AGENTS.md、CLAUDE.md（如存在）以及相关模块代码。

第二步：分析当前系统已实现的功能，不要重复开发。

第三步：针对本需求列出需要新增、修改的模块和文件。

第四步：分析 Cesium 现有能力是否满足需求，并给出实现方案及风险。

第五步：按优先级输出分阶段任务清单。

第六步：等待确认后，再开始逐阶段开发。

重要约束：

- 不要重新创建项目。
- 不要大规模重构现有系统。
